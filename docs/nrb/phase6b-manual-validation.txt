CASE 2 — 9892625b8531   CORRECTLY REFUSED    (legacy_line_ratio 0.9800 -> 0.8800)
--------------------------------------------------------------------------------
NRB Bank & Financial Institution Regulation Department circular
वै.वि.नि.वि./नीति/परिपत्र/घ/७/०७३/७४, dated २०७३/१०/१२, to class 'घ' microfinance
institutions. **The rendered page is perfectly readable Nepali.**

native-1 extraction, first lines:
    \.qfr dqT frr+f,{ kt+r.r
    q-r vqr : t.k.k.k.7ffi7qffi /q/e/o\el/t.sy ffi; Qoet/lollR
    uq' 4rf4l qEkf, ffiq q-etrTil{,

Converted output: every line REJECTED except one, which was held.

ASSESSMENT: **this is not Preeti.** The extraction is not a keystroke encoding
at all — note the repeated `ffi` runs, the same shape quoted in nrb-integration
§11 (`ffihW\ffifiHrz\reU=,.`), which are plain ASCII f-f-i, not the U+FB03
ligature. The Preeti mapping cannot recover it and the validator refused rather
than emitting confident nonsense. **CORRECT REFUSAL, and the direct answer to
question C: there are legacy documents in the benchmark that Preeti cannot
recover.** They belong in an `unknown_legacy_encoding` bucket routed to OCR.

--------------------------------------------------------------------------------

It entered the run as a genuine-Unicode control and 29 of its lines changed.

Inspection of those lines:

ASSESSMENT: those are CORRECT conversions. The document holds real Unicode

This is a THIRD false-negative class, alongside the spreadsheet gap §11.9 named:
a mixed Unicode/Preeti PDF whose Preeti minority is diluted below the threshold

this shape. It is reported, not fixed — the same discipline Task 13 followed.

CASE 7 — 8df7b02f8a13   SPREADSHEET, per-cell conversion works
--------------------------------------------------------------------------------
The benchmark's known Preeti-encoded workbook — Phase 6A's false negative,
classified `extracted`/`clean` because spreadsheets are judged structurally.

    Plss[t jflif{s cfly{s ultljlw @)&^÷&& sf] tflnsf
      -> एकिकृत वार्षिक आर्थिक गतिविधि २०७६/७७ को तालिका
    k|d'v s[lif afnLn] 9fs]sf] e"–If]q
      -> प्रमुख कृषि बालीले ढाकेको भू–क्षेत्र

ASSESSMENT: correct Nepali. Text-to-text conversion works on cell strings
exactly as it does on lines.

THE TRAP, measured: `extraction.py` renders a row as `" | ".join(cells)` and `|`
is a Preeti codepoint mapping to `्र`. Converting rendered ROWS turns every
column separator into a Devanagari conjunct. Conversion must be per CELL, which
is why `legacy_convert.convert_cells` exists and is tested separately.

Second trap, found by a test rather than by eye: Preeti maps ASCII digits to
Devanagari digits, so a numeric cell `1,234.00` converts to `ज्ञ,द्दघद्ध।ण्ण्` —
high Devanagari, no illegal clusters, no latin residue, passes every validation
rule, and destroys a number. Routing now requires the detector's own
LEGACY_MIN_LATIN share before an unjudged unit is a candidate.
